## Historical encoder issue

[FluidAudio #760](https://github.com/FluidInference/FluidAudio/issues/760) documents window-composition/right-context-sensitive word corruption in the fixed 15-second Core ML export, absent in reported NeMo/MLX comparisons. The newest model commit explicitly adds `Encoder_v2.mlmodelc` as INT8-linear re-quantization fixing token corruption. Pinned `ParakeetEncoderPrecision.int8V2` selects that file; default `.int8` still loads the old 6-bit LUT encoder. Preserve both as separate experimental variants if studying this issue.

[FluidAudio #1022](https://github.com/FluidInference/FluidAudio/issues/1022) also reports large first-load differences on physical iPhones after app updates. This is a reported issue, not a hardware capability claim established here. Cold compilation and warm loading must be separated on the user's actual phone.

## What counts as verified

Metadata verified: exact source and license read. Bytes verified: installed file hash matches immutable source. Adapter implemented: source exists, not necessarily compiled. Tested on Mac/iPhone: actual run on that hardware. Reference parity: paired comparison on identical inputs/configurations. None implies the next automatically. No community conversion here is labelled independently validated against reference.
